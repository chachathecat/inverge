# 답안길 / Professional Exam Reasoning OS 통합 마스터플랜 최종본 v11

## 한 문제를 읽되, 남의 문제집을 답안길의 자산으로 만들지 않는 학습 OS

이 문서는 답안길의 기존 핵심 기능을 없애는 계획이 아니다.

사용자는 계속 다음 흐름을 사용할 수 있어야 한다.

```text
내가 적법하게 보유·접근한 문제 한 문항 촬영
→ 문제 요구와 조건 확인
→ 내 답안·목차·계산을 먼저 제출
→ AI의 독자적 설명·힌트·첨삭·계산 검산
→ 가장 큰 간극 하나 교정
→ 자기설명·재작성·재계산
→ D+1·D+7·Review Queue·다음 행동 생성
```

그러나 일반 상업 교재, 문제집, 학원 자료와 출판사 해설처럼 답안길이
저장·검색·재사용 허락을 받지 않은 제3자 자료는 답안길의 장기 콘텐츠,
개인 cloud raw vault, 공용 문제은행, 답지 DB, RAG, embedding, 평가셋 또는
모델 학습자료가 되지 않는다.

> **원문은 한 사람의 한 학습 세션에서 필요한 최소 범위로만 처리하고,
> 답안길이 장기적으로 기억하는 것은 책의 표현이 아니라 사용자의 답안,
> 오류, 도움 이력, 교정과 다음 학습행동이다.**

법적 방어의 목표도 “증거를 남기지 않는 것”이 아니다. 권리자가 자기 책으로
직접 가입하고 문제를 촬영해 화면을 녹화하더라도 다음 사실이 드러나도록
제품을 만든다.

```text
원문 cloud 보관 0
원문·표·답지 표현 재출력 0
다른 사용자 재사용 0
문제집·답지 시장 대체형 기능 0
사용자의 선행 시도와 개인 진단 중심
한 문항·한 세션·비공개 최소 처리
독자적인 설명과 다음 학습행동
```

이 구조는 위험을 크게 줄이지만 라이선스 없는 제3자 저작물을 처리하는 이상
법적으로 절대 무위험을 보장하지 않는다. `비저장 = 복제 없음 = 자동 합법`도
아니다. 사용자의 촬영, 플랫폼의 일시 처리, AI 결과의 표현은 각각 별도로
평가될 수 있다.

### 0.1 단일 진입점

## 1. 최종 제품 정의

### 1.1 답안길이 파는 가치

답안길은 제3자 문제집을 복제해 파는 서비스가 아니다. 다음을 제공하는
개인 학습 운영체제다.

- 사용자의 문제 요구 파악
- 사용자의 선행 답안·목차·계산
- bounded hint와 자기설명 질문
- 독자적인 개념 설명과 계산 검산
- 사용자의 biggest gap
- 재작성·재계산·회상
- assistance/exposure 분리
- D+1·D+7과 Review Queue
- Personal Concept State와 다음 행동
- AI 없이 미사용 문제를 푸는 능력의 지연 검증

Primary objective는 그대로다.

```text
AI 사용량이나 답안 열람량이 아니라
unassisted held-out transfer와 delayed retention을 높인다.
```

### 1.2 답안길이 아닌 것

- 출판사별 전 문항 해설집
- 문제번호만 입력하면 답을 주는 검색엔진
- 사용자가 올린 문제를 모으는 문제은행
- 출판사 답지를 재작성하는 서비스
- 공식 모범답안·공식 채점기준
- 문제집 없이도 전 교재를 대체하는 서비스
- private upload를 다른 learner에게 돌려쓰는 서비스
- 사용자의 사적 이용을 명분으로 공용 corpus를 만드는 서비스

### 1.3 학습용 기준안 고지

생성 결과에는 기존 learner-facing caveat를 유지한다.

> AI가 생성한 풀이·기준안은 학습 참고자료이며, 시험기관의 공식 답안·공식 모범답안 또는 공식 채점기준이 아닙니다.

이 문구는 저작권 면책문구가 아니다. 실제 data flow와 output behavior가
본 계획과 일치해야 한다.

## 2. 법적 위험모델과 설계 대응

### 2.1 세 행위를 분리한다

```text
1. 사용자가 책을 촬영
2. 답안길·외부 provider가 수신·OCR·AI 처리
3. AI 결과를 사용자에게 표시
```

사용자의 개인적 촬영에 사적 이용 논거가 있어도 영리 플랫폼의 처리까지
자동 면책되는 것은 아니다. 처리 후 삭제해도 일시적 복제와 전체 이용의
목적·범위·시장효과 판단은 남는다. 결과가 원교재의 창작적 표현, 표, 사례,
목차 또는 해설을 재현하면 입력 비보관만으로 충분하지 않다.

### 2.2 권리자가 주장할 수 있는 경로

| 권리 주장 | 답안길의 공격면 | v11 대응 |
| --- | --- | --- |
| 복제권 | 이미지·OCR·표·해설의 수신·임시·영구 복제 | on-device 우선, 최소 전송, 영속 write 0 |
| 2차적저작물작성권 | 문제·해설을 변형한 사실상 새 답지 | output firewall, 독자 구조, 답지 모방 차단 |

### 2.3 운영주체 책임

개인사업자이면 Owner가 직접 민사·형사 대상이 될 수 있다. 법인도 대표자나
실행자가 직접 설계·지시·관여하거나 침해를 알면서 운영한 책임을 없애지
않는다. 이용약관에 “모든 책임은 사용자에게 있다”는 한 줄을 넣어도
답안길 자신의 처리·출력·재사용 행위를 면책하지 않는다.

따라서 법인 형태와 무관하게 다음이 실제 코드와 기록으로 존재해야 한다.

```text
권리상태 검증
업로드 제한
직원·외주자 교육
2인 이상의 고위험 변경 검토
provider 계약 검토
샘플 output 검수
신고·중단·이의제기
반복 침해 차단
감사 기록
전역 kill switch
```

### 2.4 권리자 직접 테스트를 기본 위협모델로 둔다

서버 로그가 없어도 권리자는 다음 증거를 만들 수 있다.

```text
자기 교재의 특정 문제
→ 테스트 계정과 결제
→ 촬영·업로드 화면 녹화
→ browser network record
→ AI 출력 저장
→ 원교재와 문구·수치·표·구성 비교
```

따라서 QA는 “서버에 남았는가”뿐 아니라 다음을 묻는다.

- 원문 전체를 다시 보여주는가
- 고유한 사례 순서·오탈자·특이 숫자 조합을 불필요하게 재현하는가
- 표의 행·열·값 배열을 복원하는가
- 출판사 특유의 목차·문체·암기문구를 모방하는가
- 사용자가 책 없이도 해당 교재의 답지 효용을 얻는가
- 여러 세션을 합치면 한 권의 해설집이 되는가

### 3.1 closed rights modes

### 3.2 기본값

다음은 `transient_personal_study`보다 강한 권리를 자동으로 얻지 않는다.

- 일반 상업 문제집
- 학원·강사 배포물
- 출처 불명 OCR
- 사용자가 구매했다고 진술한 교재
- 공개 웹에서 발견한 PDF
- 공공기관 사이트에 있다는 이유만으로 권리표시가 확인되지 않은 자료

`unknown`을 저장 가능한 별도 mode로 만들지 않는다.

```text
unknown commercial source
→ transient_personal_study 또는 blocked
→ 절대 owned/licensed/open으로 자동 승격하지 않음
```

## 4. 입력 정책 — 한 문제, 기본 한 페이지

### 4.1 기본 제한

```yaml
default_ocr: on_device
max_problem_pages: 1
two_page_exception: exact_same_item_only
whole_pdf: blocked
zip_epub_document_batch: blocked
continuous_pages: blocked
answer_key_pages: blocked
publisher_solution_pages: blocked
illegal_scan_or_watermark_removal: blocked
public_share: blocked
```

### 4.2 정확한 2페이지 예외

한 문항이 앞뒤 또는 마주보는 두 페이지에 실제로 걸친 경우에만 허용한다.

조건:

1. 사용자가 `같은 한 문항이 두 페이지에 걸침`을 명시한다.
2. client가 두 페이지에서 해당 문항 영역만 각각 crop한다.
3. 전체 펼침면·인접 문제·해설 영역은 제거한다.
4. page count를 늘려 전체 책을 순차 처리하지 않는다.
5. server에는 가능하면 두 이미지가 아니라 하나의 source-minimized envelope를
   보낸다.
6. exception 사용은 bodyless abuse counter에 기록한다.
7. 반복 exception은 human-safe review 또는 block 대상이다.

페이지 수는 합법성의 마법선이 아니다. 목적은 전체 책·연속 추출과 시장
대체 위험을 줄이는 것이다.

### 4.3 answer key와 해설지

다음은 transient mode에서도 처리하지 않는다.

- 출판사 정답지·해설지 페이지
- 교재 예시답안 전문
- 학원 첨삭 모범답안
- 답지를 다른 표현으로 다시 써 달라는 요청
- 특정 출판사·강사의 문체·목차·암기문구 모방 요청

사용자가 자기 답안을 올리는 것은 허용하지만, 그 답안 안에 문제·답지
표현을 길게 복사한 경우 persistence 전에 source-expression scrub을 거친다.

### 4.4 attempt-first

가능한 경우 사용자가 먼저 다음 중 하나를 제출한다.

- 답 또는 방향
- 목차·쟁점
- 계산 구조
- `cannot_start`

직접 풀이 기능을 없애지는 않지만, 기본 제품가치를 출판사 답지 대체가 아니라
사용자의 사고·오류 진단으로 고정한다. `cannot_start`이면 최소 orientation,
concept cue, structural hint 순으로 제공하고 full solution은 명시적 guided
exit 뒤에만 제공한다.

### 6.2 persistent sink의 정의

다음 모두 persistent sink로 본다.

```text

Redis durable value / KV / CDN cache
queue / scheduler / DLQ / webhook payload

backup / snapshot / PITR / replica
CI artifact / screenshot / fixture archive

training / fine-tuning / evaluation / prompt optimization

```

`private`, `encrypted`, `TTL`, `30분 후 삭제`는 저장 금지를 허용으로 바꾸지
않는다. transient mode의 cloud persistent retention은 0이다.

### 6.3 memory lifetime

- one synchronous request 안에서만 raw source를 보유한다.
- absolute memory hard ceiling은 600초다.
- 정상 completion, cancellation, timeout, client disconnect와 exception에서
  즉시 reference를 해제한다.
- 장애 복구를 위해 disk, queue, object store 또는 background retry에 raw를
  남기지 않는다.
- 실패 시 사용자가 새 session으로 다시 제출한다.
- 600초는 보관 허용시간이 아니라 비정상 요청을 강제 종료하는 ceiling이다.

### 7.1 최종 data flow

```text
        │ metadata-only session request

                                    ▼
```

### 7.2 raw processor credential absence

```text

analytics write key
```

허용 egress:

- exact provider hostname·endpoint allowlist
- bodyless receipt RPC
- closed-schema learning projection RPC
- 필요한 경우 ephemeral-key KMS operation

정책으로 “저장하지 마라”고만 하지 않는다. 저장할 권한 자체가 없도록 한다.

### 7.3 infrastructure requirements

- request buffering to disk OFF
- framework multipart temporary file OFF
- reverse proxy request-body logging OFF
- CDN caching OFF
- response caching OFF
- service-worker caching OFF for source/output routes
- session replay OFF on capture and explanation surfaces
- error reporting body/attachment OFF
- request/response body sampling OFF
- core dump and swap behavior reviewed
- `/tmp` write detection and read-only filesystem where possible
- single concurrency per session token
- hard request size and duration cap
- `Cache-Control: no-store, private, max-age=0`
- `Pragma: no-cache`
- no GET query parameters carrying source text

### 7.4 no background recovery

금지:

```text

background mode
provider polling object
webhook callback containing source
job queue
DLQ
scheduled retry
automatic cross-provider fallback
object upload followed by later processing
```

네트워크 오류가 나면 bodyless failure code만 남기고 raw는 폐기한다.

```text
출판사 답안·해설
source-minimized envelope의 reconstructable full facts
prompt와 provider request/response
문제별 전체 AI 해설
문제별 answer cache
source embedding/fingerprint/RAG
다른 사용자에게 재사용할 source-derived artifact
```

### 11.3 full output history

transient mode의 full result는 client stream only다.

사용자가 보관을 원하면:

- 사용자 기기의 local encrypted vault
- user-controlled export
- rights-cleared/user-authored mode의 별도 cloud vault

일반 상업 교재 output을 서버에 장기 저장해 cross-device history를 제공하지
않는다. local backup·sync 가능성은 정확히 설명한다.

## 12. 집단적 재구성과 남용 방지

### 12.1 금지 패턴

- 동일 책의 페이지 순서대로 반복 촬영
- 여러 계정이 분담해 책 전체 업로드
- 답지와 문제를 번갈아 업로드
- 책 제목·문제번호별 output index
- 동일 source에 과거 output 재사용
- source embedding이나 perceptual index
- publisher별 completion dashboard
- public share/export를 통한 사실상 해설집 배포

### 12.2 privacy-preserving abuse signals

사용자 upload에서 영구 equality oracle을 만들지 않는다.

허용 가능한 수단:

- 짧은 기간의 회전형 keyed HMAC
- page count와 timing 같은 bodyless pattern
- user/account/device abuse counters
- 권리자가 제공한 별도의 차단 fingerprint registry
- notice에 의해 지정된 publisher/edition/item block rule

회전형 HMAC는 원문 검색, shared dedup corpus, 다른 사용자 답변 재사용 또는
rights promotion에 사용하지 않는다.

### 12.3 repeat infringer

정책 위반은 closed reason code로 기록한다.

```text
warning
→ transient feature cooldown
→ source class/publisher block
→ account suspension
→ termination
```

명백한 불법 스캔·전체 답지·반복 우회는 즉시 suspension 후보다. 사용자는
오탐에 대해 이의제기할 수 있다.

## 18. Incident Response

### 18.1 automatic hold conditions

다음 중 하나면 feature 또는 route를 즉시 hold한다.

- raw/OCR/prompt/provider output이 persistent sink에서 발견
- source-bound full output이 cloud history에 저장
- provider retention status unknown/stale
- cross-user reuse, RAG, embedding, training/eval 발견
- publisher output reproduction severe finding
- valid notice 뒤 처리 지속
- page/answer-key/bulk defense 우회
- privacy notice와 실제 flow 불일치
- legal review blocker

### 18.2 response

```text
kill route/feature
→ preserve bodyless incident metadata
→ revoke credentials and purge unauthorized copies
→ scan every sink and backup domain
→ identify affected sessions without reconstructing source
→ provider/legal escalation
→ required user/authority/rights-holder notice
→ root-cause correction
→ hostile regression
→ fresh counsel/Owner release decision
```

자동 resume하지 않는다.

### 18.3 deletion language

허용 표현:

```text
답안길의 persistent application stores에 원문을 기록하지 않았습니다.
처리 프로세스의 application reference가 해제되었습니다.
```

금지 표현:

```text
모든 RAM bit와 provider infrastructure에서 물리적으로 완전 소거되었습니다.
어떤 법적 책임도 존재하지 않습니다.
```

- evaluation/training 여부
- output download/share

## 24. 최종 불변식

1. 비저장은 자동 합법이 아니므로 목적·범위·output·시장효과까지 통제한다.
2. 권리자의 직접 테스트와 화면녹화를 방어 가능한 제품을 만든다.
3. 일반 상업 교재는 기본 한 문항·한 페이지·한 사용자·한 세션이다.
4. 두 페이지는 같은 한 문항의 불가피한 예외만 허용한다.
5. on-device OCR과 source minimization이 기본이다.
6. raw source의 cloud persistent retention은 0이다.
7. raw processor는 저장 credential 자체를 갖지 않는다.
8. queue, background, object upload, prompt cache와 retained fallback을 금지한다.
9. provider eligibility는 exact org/project/endpoint/model/capability와 계약에
   묶고 drift 시 block한다.
10. 원문뿐 아니라 full source-bound AI output도 server에 저장하지 않는다.
11. 학습 원장에는 scrubbed learner body와 non-reconstructable closed evidence만
    남긴다.
12. 원문·표·고유 사례·답지 목차를 재현하는 output은 release하지 않는다.
13. transient source를 다른 사용자, RAG, embedding, training, eval 또는
    verified held-out에 사용하지 않는다.
14. 전체 책·답지·연속·분할 추출은 기술적으로 막는다.
15. notice를 받으면 즉시 hold하고 counter-notice·repeat-infringer와 kill switch를
    운영한다.
16. 법인과 사용자 약관은 대표자·운영자의 직접 책임을 자동으로 없애지 않는다.
17. 직원 교육, 독립 검토, audit와 actual enforcement가 있어야 한다.
18. public docs와 marketing은 실제 data flow보다 강한 주장을 하지 않는다.
19. deletion receipt는 logical no-persistence를 증명하며 physical bit erasure를
    과장하지 않는다.
20. 실제 제3자 source pilot 전 current provider contract와 한국 저작권·privacy
    written review를 다시 받는다.
21. full cloud history, search, RAG와 unrestricted companion 기능은 license에서
    연다.
22. 답안길의 장기 자산은 남의 문제집이 아니라 사용자의 독립 학습능력에 대한
    비복원적 evidence다.
